# Household Battery Trading Optimisation in the NEM

Final year project, B.E. Electrical & Electronic / Computer Systems Engineering,
The University of Newcastle.

The project models a household battery with rooftop solar operating in the
Australian National Electricity Market, and compares three ways of running it:
a degradation-aware MILP with perfect foresight, the same MILP driven by price
forecasts in an MPC loop, and self-consumption on a retail tariff.

## Repository layout

```
report/    LaTeX source for the written report  →  report/README.md
code/      simulations, forecasting and plots   →  code/trading/RESULTS.md
```

The two are kept separate deliberately: `report/` is written prose that compiles
to a PDF, `code/` is what produces the numbers that prose reports.

### `report/`

`cd report && latexmk -pdf main.tex`, which writes `report/build/main.pdf`.
`main.tex` is an outline of `\input` lines;
each chapter is its own file under `chapters/`. See
[`report/README.md`](report/README.md).

### `code/`

| Path | Contents |
| --- | --- |
| `code/trading/` | Battery dispatch: MILP, forecasting/MPC, retail, state machine. |
| `code/data_exploration/` | Early NEM price and demand analysis feeding Chapter 5. |

Entry points are the drivers in `code/trading/`:

```bash
cd code/trading
python milp_trading.py          # perfect-foresight MILP
python forecast_trading.py      # forecast-driven MPC
python retail_trading.py        # retail self-consumption
python state_machine_trading.py # threshold state machine
```

Per-run CSVs and plot pages are regenerated by the drivers rather than tracked;
see `.gitignore` for what is kept.

### Where the written results come from

`report/chapters/05-results.tex` reports numbers produced by `code/trading/`.
The working notes behind it are:

| Document | Covers |
| --- | --- |
| `code/trading/RESULTS.md` | Every reported number, with its source CSV. |
| `code/trading/milp/MODEL_NOTES.md` | MILP formulation and degradation model. |
| `code/trading/FORECAST_NOTES.md` | Forecaster design decisions. |
| `code/trading/retail/MODEL_NOTES.md` | Retail tariff model. |

When a simulation is re-run, the notes and the results chapter both need updating.
